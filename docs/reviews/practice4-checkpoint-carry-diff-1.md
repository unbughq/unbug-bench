## Findings

### 1. BLOCKING: the design's "smoke-before-practice" acceptance test is missing, and nothing in the code enforces the ordering
- **Evidence:**
  - `docs/designs/practice4-checkpoint-carry.md:61` lists "smoke-before-practice" among the required tests.
  - `tests/factory/test_practice4_carry.py` has only three tests (`:86`, `:102`, `:115`), and none of them reserves `practice`.
  - Under -4, a fresh `practice` reservation follows this path:
    1. `batch_holder.reserve` runs `prepare`.
    2. `_admit` takes the branch at `batch_holder.py:305-310`, which only refuses a job that already exists in the source snapshot.
    3. `money.authorize_locked` runs.
  - Nothing requires the imported smoke continuation to have been retired first. Only `max_concurrency=1` and the runbook text (`docs/designs/practice-run.md` addition: "Do not reserve or dispatch the dormant practice job…") stand in the way.
  - A grep for smoke ordering in `factory/*.py` finds nothing apart from the Boat decision selectors.
- **Why it blocks:** the implementation-readiness standard requires the test plan named in the design to be implemented. The design names an ordering property that is neither tested nor enforced. Under this standard, closing the gap is not left to the implementer's judgement.
- **Suggested fix (choose one and record it in the review file):**
  - (a) Add a test to `test_practice4_carry.py`. After `transfer.prepare`, it calls `holder.reserve(policy, root, home, 'practice', None)` and asserts a refusal (`MoneyWait` or `ValueError`) until the imported smoke operation is retired. Add the smallest guard in `_admit` only if one is needed, which the design does not currently authorise.
  - (b) Amend the design so the test list says "smoke-before-practice is procedural (runbook ordering + separate go-ahead), not code-enforced". Then add a test asserting that practice stays unreserved because it is dormant. For example, `practice.active` with no opt-in refuses.

  Option (b) is the smaller change and fits "add no generic practice framework" better.

### 2. NIT: commit 07df660 is a legitimate adaptation, but its comment overstates what covers the -4 path
- **Evidence:**
  - `tests/factory/test_boat_retirement.py:37-41` patches `practice.BATCH` and `practice.EXPECTED` to the retained -3 manifest.
  - `:50-52` appends the same pin, labelled AUTHORED, to the copied `factory/practice.py`. This happens before `key_holder.fingerprint(self.root)` and before the `host_files` hashes are computed, so the authored release stays self-consistent.
- **Not a production regression:**
  - `batch_holder.reserve` already called `batch_transfer.prepare` unconditionally on `factory-simplify` (base `batch_holder.py:364-367`), and `prepare` returns at once when `carry_from` is absent (`batch_transfer.py:200`). The branch changes no reservation code.
  - Under -4, a fresh smoke reservation (`source_generation=None`) is correctly refused by design: `batch_money.py:348` raises `MoneyWait` for any carried job. So the test's "fresh smoke reservation" scenario cannot exist under -4. Pinning it to -3 is the only meaningful way to keep this retirement regression.
  - The commit message gives the proximate cause: the predecessor release is missing in the authored layout. The more basic reason is that a carried job refuses fresh admission.
- **Gap:**
  - The new comment says "the -4 whole-batch carry (imported smoke) is covered by test_practice4_carry.py". That file covers only `prepare` and `source`.
  - Nothing exercises the path the live -4 continuation will actually take:
    - `reserve` with `source_generation=b615…`
    - `_config` for an imported op (`job_config.py:106-121`)
    - `boat_lifecycle` retirement authority with `--checkpoint-sha256` equal to the imported generation (`boat_lifecycle.py:304-311`)
- **Suggested fix:**
  - Reword the comment and the commit message to "fresh-reservation retirement is retained on -3; -4 prepare/source is covered by test_practice4_carry.py; -4 imported-continuation retirement is not covered offline".
  - Optionally, under the open `new-boat-stop-capture-1` work, add an -4 retirement-authority case that reuses the `test_practice4_carry` layout.
