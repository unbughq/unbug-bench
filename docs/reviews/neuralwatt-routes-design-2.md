## Blocking

**NB1 (B2 partly fixed): `open_steps` can't be read where the tail is computed, and isn't always an upper bound.** `starts`/`finishes` are locals of `_run_budgeted` (`budget.py:1066`), lost when the `BudgetError` propagates. `_settle_leaf` (`budget.py:423-432`) sees only the `model_runtime.py:672-688` receipt, which has no step field. When cancellation fails, `starts` gets a `cancellation-failed:` marker (`budget.py:1536`, `:1552`) and the no-gate process may keep spending; without a gate (`_gate_bound`, `:362-371`), "open steps × one request" is not a bound. Fix: in `_run_budgeted`'s exit transaction, write `invocation_reservations[lease_id]['open_steps']` for a reserved call, counting only OpenCode `session:messageID` keys in `starts - finishes`. In `_settle_leaf`, for `NW_ROUTES`, use `min(bound − booked, open_steps × nw_request_worst)` only when the field is present, no `cancellation-failed:` or `unverified-*` key is open, and `cleanup_errors` didn't grow; otherwise keep `bound − booked`. Consider `max(open_steps, 1)` for stops that aren't a classified credit/rate/quota refusal (stall, timeout), since a request can be in flight before its step-start part appears. Add a cancellation-failed test.

**NB2: "keeps `plan_list_cost_usd`, the same as Go" counts every NW step twice.** `event_bound_charge` is `cost + plan_list_cost_usd` (`budget.py:135-141`), and so is `_bounded_cost` (`:201-203`); `worker_step.py:754` adds `plan_list_cost_usd` to the reported list total. Booking cost = X and plan_list = X makes the reservation check count 2X: the call is stopped as `model_call_cap` at half its window, and its list cost is reported double. Fix: for NW, set the part cost to `max(part cost, go_step_cost)` and leave `plan_listed = None` (no `priced:'plan'`, no `plan_list_cost_usd`). Test that an NW event has no `plan_list_cost_usd` and that `event_bound_charge == cost`.

**NB3 (B4 partly fixed): step 4 can stall every case, and the key never reaches the router.** "If the bundle lacks the key, step 4 is undone, because pack raises" is false. `worker_credentials()` re-reads `bundle_file` on every worker delivery (`runtime.py:244-255`, `workers.py:581-595`); `pack` raises (`router_delivery.py:79-80`), giving `infra:credentials_unavailable` (a WAIT, `stop_registry.py:60`) for every new worker, and nothing reverts. Copying the bundle in takes effect at once, before the restart, and `setup-secrets` partial updates start from the Mac's `$UNBUG_SECRETS_FILE` (`bin/setup-secrets:32-35`), so a Mac copy missing any VM key breaks delivery immediately. The router reads config `accounts` only at startup (`model_router.py:1153-1156`); step 4 restarts only the controller, so the lane stays off. Fix: step 2 adds `neuralwatt-key` to the router config `accounts` before the drained restart (harmless; no caller offers it). Step 4: back up `bundle_file` and the config; on the VM, check the new bundle before install (`age -d -i <identity_file> <new> | tar -t` lists every `worker_credentials.accounts` name plus `neuralwatt-key`); swap it in with `mv`; then edit the config and restart the controller. Rollback: restore both backups and restart.

**NB4: phasing. Item 8 and the move-on test depend on data captured after the release ships.** Item 8 and the move-on test need the 402/429 bodies from rollout step 5, but step 1 merges and installs before that, and step 6 sends that same release, with no follow-up release between. Step 1 also makes the release current for new batches, so after step 4 (every new box has the key) a batch launched before step 5 uses Neuralwatt before the smoke test, against "before any case gets the release". Fix, pick one and write it down: capture the bodies before merge with a one-off direct API call on the trial key, commit them as fixtures and land item 8 in this branch; or add explicit steps (no new batch uses the release until step 5; then merge the follow-up, install, drained restart, before step 6).
