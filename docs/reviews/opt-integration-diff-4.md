### Findings

1. **Blocking — Recertification can still seal one-reviewer G8/G9 verdicts.** [factory/run.py:3531](/Users/bugsincode/Developer/unbug-bench/.claude/worktrees/opt-integration/factory/run.py:3531) retains the October G8/G9 passes even when a second reviewer is newly adopted. For a legacy seal with one reviewer and an eligible second family, the card names two reviewers, but the second never approves fairness or realism. The new test covers only *no eligible reviewer*. The architecture guide promises historical verdict reuse, while the current factory rule requires two approvals; that conflict needs resolution. **Weakens the exam: yes**, unless the historical exception is explicitly intended.

2. **Blocking — An already-selected former role family remains reviewer2.** [factory/run.py:3191](/Users/bugsincode/Developer/unbug-bench/.claude/worktrees/opt-integration/factory/run.py:3191) only selects or checks reviewer2 when the card has one reviewer. A case checkpointed under the old code after the reported z-ai → Xiaomi stress swap can already have z-ai as reviewer2; deploying this fix leaves that panel intact. The test covers new adoption and repicking, not an existing affected card. **Weakens the exam: yes**—the reviewer can judge repairs prompted by its former stress work.

3. **Blocking — A cached G2 pass bypasses the new swap count.** [factory/run.py:1888](/Users/bugsincode/Developer/unbug-bench/.claude/worktrees/opt-integration/factory/run.py:1888) returns a retained pass without checking the freshly computed `own_search` count. Within the receipt lifetime, swap stress tester A → B → A before another G2 pass: the old model and evidence binding match again, even though the current count after the latest swap is zero. A read-only in-memory check returned the old pass with two searches while the current count was zero. The new test exercises the counter alone. **Weakens the exam: yes.**

4. **Blocking — Mutable timestamps do not establish who searched.** [factory/run.py:1819](/Users/bugsincode/Developer/unbug-bench/.claude/worktrees/opt-integration/factory/run.py:1819) treats a row timestamp after the swap as proof it belongs to the new tester, but the agentic fallback copies old rows to that tester and permits their `at` fields to be changed. Updating two timestamps alone makes the old queries count; the new test itself performs a timestamp-only change. Pre-fix swap records also have no `at` and are silently ignored. **Weakens the exam: yes**—G2 can pass without the replacement tester’s own searches.

5. **Blocking — New GATES inputs are incompatible with pinned old workers.** [factory/durable/engine.py:1055](/Users/bugsincode/Developer/unbug-bench/.claude/worktrees/opt-integration/factory/durable/engine.py:1055) adds `g10_usd_micros` without checking the selected plumbing release. An older worker’s strict decoder rejects that unknown field. This can occur when a controller is switched while a batch still names an installed older release; the rejected start can be treated as an absent, lost attempt and charged. The test checks field presence with the current worker, not cross-version dispatch. **Weakens the exam: no.**

6. **Blocking — An interrupted old lost-attempt settlement cannot replay.** [factory/durable/executor.py:288](/Users/bugsincode/Developer/unbug-bench/.claude/worktrees/opt-integration/factory/durable/executor.py:288) now calls `settle_lost`. If the immediately preceding implementation committed its smaller `grant − extension` settlement and crashed before DBOS recorded completion, recovery calls the new path against an already settled ledger row. The ledger rejects the contradictory settlement, preventing progress. This condition depends on that preceding implementation having run; the fresh-attempt test does not cover the crash boundary. **Weakens the exam: no.**

7. **Should-fix — Earlier G10 spending consumes a fresh batch-funded reserve.** [factory/budget.py:252](/Users/bugsincode/Developer/unbug-bench/.claude/worktrees/opt-integration/factory/budget.py:252) subtracts lifetime G10 spending from each new authority. After diagnosis, a new GATES sequence draws fresh batch funding: with $120 spent on earlier G10 tries and a new $200 grant, ordinary calls can use $170 rather than $50. They can therefore spend authority reserved for new G10 work. The retry test covers a case-capped grant, not this batch-funded sequence. **Weakens the exam: no.**

8. **Should-fix — A partial grant can reserve the entire grant for G10.** [factory/budget.py:253](/Users/bugsincode/Developer/unbug-bench/.claude/worktrees/opt-integration/factory/budget.py:253) reserves `min(grant, $150)`. If the $200 request receives $100, ordinary calls get $0 even though the original $50 request was fully fundable. This edge predates the reviewed correction but remains in its reserve calculation; the tests use a full grant or no authority. **Weakens the exam: no.**

9. **Should-fix — Signal and some local failures still look like Boat refusals.** [factory/durable/guard.py:698](/Users/bugsincode/Developer/unbug-bench/.claude/worktrees/opt-integration/factory/durable/guard.py:698) recognizes unsigned exit codes of 124 or more, but `BoatCli.probe` passes a subprocess killed by SIGKILL as `-9`. Repeated `exit_-9` renewals are recorded as refusals and can retire a silent live worker. Some local wrapper failures also return `1`, which is indistinguishable here from a refusal. The regression covers timeout `124` only. **Weakens the exam: no.**

10. **Should-fix — Existing INPUTS-pinned reviewers lack the new pin marker.** [factory/run.py:3168](/Users/bugsincode/Developer/unbug-bench/.claude/worktrees/opt-integration/factory/run.py:3168) restores the pin only from `reviewer2_pinned`, which the new ADMIT code did not write into older snapshots. A later swap into that reviewer’s family can still silently repick it. The regression manually inserts the marker and does not cover an old snapshot. **Weakens the exam: no**, assuming the replacement is otherwise independent.

11. **Should-fix — Empty and unset dependency-image variables share an identity.** [factory/gate_state.py:46](/Users/bugsincode/Developer/unbug-bench/.claude/worktrees/opt-integration/factory/gate_state.py:46) treats `MEDUSA_DEPS_IMAGE=""` as unset and binds the `/opt` file. `bin/bench.py` reads that file only when the variable is absent; an explicitly empty value is passed to Docker instead. A pass saved with the variable absent can therefore be reused under a different execution environment. The new test changes the file while the variable is absent. **Weakens the exam: yes**, in that configuration.
