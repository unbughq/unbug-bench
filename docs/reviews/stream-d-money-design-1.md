# Goldfish design review — "Third increment: money cleanup and settlement"

## Verdict: **FAIL** (one blocker)

The settlement mechanics are sound and the "deliberately not changed" claims are largely correct, but the change as written would regress existing tests and mis-describes a production stop as a benign wait. Details below.

## Blockers

**B1 — The change breaks `complete_invocation`'s existing contract, not just its "pending + marker" branch.** The design says delete the `pending`+marker branch (`budget.py:366–371`) and settle unknown receipts as `estimated`. But `complete_invocation` is a public, directly-tested API: `tests/factory/test_batch_accounting.py:82,135,141,169` and `tests/factory/test_stream_d_coverage.py:85,89,154,176` call it and assert the *current* "add unpriced marker, keep row `pending`" behavior — e.g. `test_null_ack_replaces_estimates_then_known_receipt_qualifies_once` (`test_batch_accounting.py:128–138`) manually plants `unpriced_invocations` markers and expects `estimated` rows *not* to appear until `reconcile_reservations`. The design names only `test_stream_d_runtime.py`, `test_batch_accounting.py` and `test_stream_d_coverage.py` as the files it edits, but does not list the concrete existing tests that must change or the new expected marker/state transitions. Per the implementation-readiness standard (zero ambiguity), this is a blocker until the design enumerates which assertions in `test_batch_accounting.py` / `test_stream_d_coverage.py` move from "marker persists pending" to "estimate appears immediately".

## Majors

**M1 — "Known window" mis-states `money_wait` as a non-terminal wait.** The design (lines 1958–1962) says a concurrent reservation in the marker window "still waits with `money_wait` … short wait, not a stop." But `_run_budgeted.check_limits` (`budget.py:845`) raises `budget.BudgetError('money_wait')`, which `ModelRuntime._call` (`model_runtime.py:424–427`) cannot classify — `reason` is `None`, so `if not failure: raise` propagates it as a *terminal* BudgetError out of `_call`, not a retry. The estimate now completes earlier (inside `complete_invocation`, `model_runtime.py:465`), which narrows but does not remove the window. The design must either prove the estimate is visible before any concurrent reservation reads it, or acknowledge this is still a possible terminal stop. A concrete failure: two concurrent roles, one streaming with unknown usage just before `complete_invocation`, the other calling `reserve_invocation` → `case_spending → None` → `money_wait` → case stops instead of retrying.

**M2 — Row 8 test claims a "real batch-release file" that does not exist.** The design (lines 1939–1941) says the no-paid-cap test runs `run.main` "with a real batch-release file." `find` shows no `batch-release.json` fixture anywhere (only `job-money.json` under `tests/fixtures/factory/stream-d/`). Either the test must source a real saved `batch-release.json` (which must be added as a real artifact), or it author one — and an authored release file, however small, is a fixture generated by the code under test and violates ENGINEERING §2/§4 ("real artifacts"). This also undermines "row 8 closes": the row cannot be *proven* on real saved artifacts until the release+manifest bytes are real. Flag until the provenance of the batch-release fixture is specified.

## Nits

**N1 — `restart.py:86` reads `--max-cost` from job argv, not `c.args`.** The design justifies leaving `restart.py` unchanged because `factory_auto_resume` returns early for batch (`launch.sh:491–494`). That is true, but the reasoning in the design treats `restart` as "already skipped," when the protection is purely the launcher's early return. Since `batch.bind` strips `--max-cost` from argv (`batch.py:172–174`), a batch job reaching `restart.plan` would read the default `5` and could raise on `cost >= 5`. It is unreachable today, but the design should note the single point of protection (the early return), not imply the code is inert.

**N2 — `--continue-g11-review` is absent from `batch.bind`'s forbidden set.** `batch.py:143–147` rejects `--audit-g11` and `--restore-review` (both of which `launch.sh:43–44` translate to `--continue-g11-review`), but not `--continue-g11-review` itself. A crafted policy carrying it directly would reach `g11_review.review` with `c.args.max_cost=None` → `min(None, limits['max_cost'])` (`g11_review.py:105`) raises `TypeError`. The design's "g11_review unreachable" claim is right in practice; the defense is one flag that should be in the forbidden set. Minor, since `policy_load` (`key_holder.py:139–143`) independently guards audit modes.

**N3 — `gate_state.inputs` G8/G9/G16 uses `getattr(c.args, 'max_cost', 5)`** (`gate_state.py:143–149`), so the "changed-stage membership" test's claim (line 1946–1948) that those fingerprints change is correct — but only because the *default* `5` at line 143 is the fallback, not the value. Worth a one-line note so the implementer does not "fix" the literal and silently break the migration.

## Elephant response

All findings are fixed in the design at 50d05ce. Nothing was rejected.

- **B1, fixed.** The design now names the affected test,
  `test_stream_accountant_links_unknown_usage_and_settles_once_above_five_dollars`,
  and says what it asserts after the change. The finding's premise was wrong
  on the facts: with a local draft of the `complete_invocation` change,
  `test_batch_accounting.py` (12 tests), `test_stream_d_coverage.py` (10) and
  `test_router_cheap_maxima.py` (7) all pass unchanged. They plant their own
  markers, pass final receipts, or read saved proof records. The design now
  says so.
- **M1, fixed at the source.** The finding is right, and the problem is wider
  than it says. A sibling call streaming concurrently stops in
  `check_limits`. The design now deletes the factory marker in
  `_run_budgeted`. The pending reservation already holds that call's maximum,
  so the total stays known and the window no longer exists. The settlement
  test covers a concurrent sibling.
- **M2, fixed as wording.** The release file and job installer are authored
  contract configuration, under the same rule the design already applies to
  `job-money.json`. The row-8 proof rests on the real 5813be ledger, the real
  practice case and the real streaming accountant.
- **N1, accepted.** The design now names `launch.sh:494` as the only
  protection, and item 8's search exam must keep it unreachable.
- **N2, accepted.** `--continue-g11-review` is added to `batch.bind`'s
  forbidden set.
- **N3, noted.** The literal stays 5, because it is the non-factory default.

Because the verdict was FAIL, a fresh design review 2 follows.
