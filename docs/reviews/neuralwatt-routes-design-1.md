# Design review 1: neuralwatt-routes (goldfish, Mode: REVIEW, zoom_out + design_critic + implementation_readiness)

Verdict: **FAIL**. 7 blocking, 7 nits. All line refs in `/Users/bugsincode/Developer/ub-neuralwatt`; read-only, nothing changed.

## Answers to the six questions

1. **Can a running case on an older release be leased an NW lane?** No today; yes after the next plumbing release rolled onto a running batch (B1). The worker sends `accounts` = `_account_order(case)` (`factory/model_router.py:854-861`), built from the worker's own `ACCOUNTS` (no production code sets `router_accounts`), so an old worker never offers `neuralwatt-key`; the router keeps only accounts in its config (`:516`) and `routes()` only labels an NW route with an offered account (`:164-167`). Backstop: the old worker's `_admit` (`:875-879`) checks the lease against its old CHAINS and would reject it anyway.
2. **Does twin-list booking bound the charge?** Per completed step, yes. The unseen tail doesn't: it books the whole funded window, up to $50 (B2). And every step can book $0 if usage isn't streamed (B3).
3. **Paid-pool code assuming every paid lane is OpenRouter:** none found. `paid_reserve`, `_unfunded`, `lift_credit`, `credit_stuck` and `credit_ready` key on `GATED_OPENROUTER` membership or `PAID_POOL`, never `billing == 'paid'` (`:651`, `:666`, `:383-385`, `:708`, `:1114`). Side effect: the router's paid ceiling doesn't cover NW spend (N5).
4. **Walled roles / family / funded_maximum / valid_lease:** family holds (mimo→xiaomi, glm→z-ai, `:121-127`). `funded_maximum` gives NW the gated-OpenRouter $50 cap (`:99-100`). Worker-side `valid_lease` calls use the new `ACCOUNTS` (`factory/model_runtime.py:72`, `:562`, `:773`). Walled exclusion also needs `bounded_route` (`factory/model_runtime.py:188-192`), not only `ungated_lanes` (N4).
5. **Key delivery "like opencode-go-key":** implementable, but the design leaves out the steps that brick every worker if done in the wrong order (B4).
6. **Test gaps:** see B2, B3, B5, B7, N1.

## Blocking

**B1. "New launches only" rests on release pinning, which the factory's own rule removes.** `factory/durable/engine.py:938-945` and `:2113-2115`: each attempt takes the batch's latest `plumbing` release, and ENGINEERING §3 says plumbing rolls onto running cases at the next checkpoint. The first later plumbing fix sent to a running batch carries the new ACCOUNTS/CHAINS, so running cases would offer `neuralwatt-key` and take the NW lane, against the founder's rule that running cases stay on OpenRouter. The rollout line ("new launches and relaunches") also conflicts, since a relaunch is a running case's resume. Fix: gate the offer on something fixed at launch, not on the release, e.g. offer `neuralwatt-key` only when the case card was launched with a `neuralwatt` provider-account marker (the card already has `provider_accounts`). Add a test that an old card on new code gets no NW lane. Ask the founder to rule on relaunches.

**B2. The unseen tail books the whole funded window as case money, and then move-on fails.** The tail is `bound - booked` (`factory/budget.py:425-432`). NW has no gate, so `_gate_bound` is None (`:370-371`: 0 forwarded, not exhausted) and the bound is the full `maximum_usd`. A writer's window is uncapped, up to $50 (`factory/model_runtime.py:50-62`, `factory/model_router.py:99-100`). `final_usage_known` needs `outcome == 'done'` (`factory/model_runtime.py:640-650`), so every 402, quota, stall, timeout or cancel leaves the tail unseen. The $5 trial *will* run out mid-call: one 402 books about $50 to the case with $0 actually charged, and the "move-on to OpenRouter" then dies with `budget_exhausted:grant_insufficient` because the phantom tail ate the money. The move-on test doesn't check money, so it won't catch this. Fix: bound the NW tail by what was in flight: step starts without a finish × one request's worst case at the twin price (context×in + output×out, about $0.57 for MiMo), and $0 with no step in flight. Add a budget test from a real 402 receipt with no steps, asserting a $0 tail.

**B3. With no `includeUsage`, every NW step can book $0.** The design's provider options (doc line 63) are only `baseURL`/`apiKey`. OpenRouter usage arrives only because the gate forces `stream_options.include_usage` (`factory/model_call_gate.py:398-402`); NW has no gate. As far as I know, `@ai-sdk/openai-compatible` only asks for streaming usage with provider `includeUsage: true` (not verified: no web access). Without it OpenCode reports 0 tokens, so `max(0, go_step_cost(0 tokens))` = $0, and real spend goes unbooked until the `zero_tokens` stop. Fix: put `includeUsage: true` in the provider options. Have the smoke call assert non-zero tokens, and save its step part as the budget-test fixture; the design's "Go fixture shape" isn't an NW response.

**B4. Key delivery is under-specified, and the wrong order stops every worker or the controller.** Every worker box gets keys from `worker_credentials.accounts` (`factory/durable/runtime.py:222-227`, `:244-255`). `pack` raises on any listed name missing from the bundle (`factory/router_delivery.py:64-68`), which fails every worker's credential step with `infra:credentials_unavailable` (`factory/durable/workers.py:581-595`) and stops all running cases. The controller refuses to start if the config lists a name its `ACCOUNTS` lacks (`invalid_worker_accounts`, `factory/durable/runtime.py:224-226`). `bin/setup-secrets` has no `neuralwatt` step (lines 27-28, 64-81). Fix: write the runbook into the design in this order: (1) router restarted drained on new code; (2) controller restarted on new code; (3) founder runs `bin/setup-secrets neuralwatt`, copies the re-encrypted bundle to the VM's `bundle_file`, then adds `neuralwatt-key` to `worker_credentials.accounts` (and to the router config `accounts` if that's set explicitly); (4) controller restarted. Also spell out the `setup-secrets` step (prompt, key format check if any, output file name `neuralwatt-key`).

**B5. "Key file exists" filtering in only one place leaves other worker callers able to loop.** `ordinary_retry.py:127-140`, `await_lease` (`factory/model_router.py:951-952`) and preflight (`factory/run.py:473`) all build routes from `getattr(c, 'router_accounts', ACCOUNTS)`. On a new release without the key (the gap between B4 steps 1 and 3), the NW route counts as "approved" but can never be spent, so `exhausted()` never comes true and a malformed-answer retry falls into the loop fixed for cae763. Fix: work out offered accounts once, when the case context is built (`c.router_accounts = ACCOUNTS minus keys with no file`), and drop the special filter in `_account_order`.

**B6. The OpenCode model `limit` is left as "…".** Doc line 63 says `limit: …`. For a custom model, a missing or zero context likely switches off OpenCode's auto-compaction, and MiMo sessions grow to hundreds of thousands of tokens. That is an implementer decision with real money impact, which the Zero-Decision Rule forbids. Fix: give exact `context`/`output` per model, from `/v1/models` (saved as a fixture) or from the twin's `GATED_OPENROUTER`.

**B7. The Murphy row is "closed" by synthetic tests.** ENGINEERING §2 requires a test on real artifacts; the routes and move-on tests are config-only. Fix: close `new-neuralwatt-1` with a test that takes a real saved MiMo/GLM card and the 11-19 router state (credit block on `openrouter-key` plus Go quota block) and checks that acquire gets `neuralwatt-key/neuralwatt/…`. Use a real NW 402 body saved from the trial for the move-on test (N1).

## Nits

- **N1. 402 wording unknown.** If NW's out-of-credit error isn't a 402 and lacks "insufficient credits", `classify_provider_failure` (`factory/budget.py:42-47`) returns None: the stop becomes `opencode_error` with no health block, and every retry goes back to NW. Capture the real body in the trial and pin it in a test.
- **N2. Classify mapping is vague.** Item 7 says "router:…_limit". Name the exact code; if it's new, add it to `factory/durable/stop_registry.py:59` and `PUBLISHED_REASONS`. Without the `neuralwatt/` prefix, `classify.py:400-403` leaves an NW 402 as `router:credit`, which parks the case waiting for an OpenRouter top-up.
- **N3. Pool capacity not stated.** Router config `capacities` defaults to 1 seat per pool (`factory/model_router.py:475`). State the `neuralwatt-key` seat count, and that `disabled_routes: ["neuralwatt/"]` is the off switch once the trial is spent.
- **N4. ACCOUNTS slicing and walled roles.** `ACCOUNTS[2:4]` is positional (`factory/model_router.py:161`, `factory/model_runtime.py:392`), so say "append `neuralwatt-key` at the end". Also change `bounded_route` (`factory/model_runtime.py:188-192`) for walled roles, not only `ungated_lanes`.
- **N5. No router-side money ceiling for NW.** `paid_ceiling_usd` doesn't cover it (`_unfunded` returns False, `:651`); only case and batch money bound it. Say so.
- **N6. Price evidence not saved.** Save the `/v1/models` response and the pricing page as a dated fixture, like `router-*-price-record.json.gz`. "Never bills above list" has no recorded evidence today.
- **N7. Heilmeier gaps.** No timeline, build cost or success metric (e.g. NW share of MiMo/GLM spend, dollars saved). The Impact section should also say the seven parked cases stay on OpenRouter, so this change doesn't unblock them.

Verdict: **FAIL**

## Elephant response (2026-11-19)

- **B1:** fixed by restating the rollout, not by a launch-time marker. The founder asked on 2026-11-19 ("Let's do it for existing launches too, or is it not possible") for running cases to use Neuralwatt where possible. The design's "running cases stay on OpenRouter" was the elephant's own limit, not a founder rule. The real limit is the standing rule against new plumbing releases to cases past G10. The design now says: the lane reaches a case when its batch is sent the release (`plumbing_release <batch>`, the operator's per-batch choice), never to cases past G10; and the switch-on is the key in `worker_credentials`. A test pins that an old-ACCOUNTS caller gets no lane.
- **B2–B6:** fixed in the design, as specified.
- **B7:** fixed. The routes test uses the real 11-19 router health rows. The move-on test uses the real 402 body captured on the trial, before go-live.
- **N1–N7:** taken.
