# Durable execution: wave 1 briefs

**Status: ready.** Design review 5 passed. The founder decisions at the end of the design come before launch.

These are briefs for the seven wave-1 packages of `docs/designs/durable-execution.md`.
Each brief is the whole prompt for one agent. The agents run in parallel, each in its
own worktree, on its own branch `de/<id>`, cut from `durable-execution`.

## Rules every package follows

- **Read first:**
  - `docs/ENGINEERING.md`;
  - `docs/designs/durable-execution.md`;
  - `factory/durable/contract.py`;
  - the three design reviews' resolution tables (`docs/reviews/durable-execution-design-*.md`).
- **Write only the files your package owns** (the design's work-package table).
- **Do not edit `factory/durable/contract.py`.** If you believe it is wrong or
  missing something, stop and report it as a finding. A contract change goes through
  the design and a design review.
- **Design note.** Write `docs/designs/durable-execution-<id>.md` before code: what
  you build, which contract seams you implement or call, your tests, and the Murphy
  rows you target.
- **Tests use real artifacts** (ENGINEERING section 4): real DBOS on SQLite, real
  `age`, real saved Boat CLI outputs, the real public practice case. No fixture
  generated by the code under test.
- **While working,** run only your own test files:
  `BENCH="$PWD" uv run -q --with numpy --with scipy --with dbos==3.4.0 python -B tests/factory/<file>`.
- **Once, on the exact head you hand back,** run the full suite:
  `uv run --with numpy --with scipy --with dbos==3.4.0 python -B tests/run.py`.
  These seven scripts already fail in a cloud sandbox and are not yours:
  - `test_boat_legacy_debit` (when the checkout is under `/home/user`);
  - `test_practice_startup`, `test_preflight`, `test_recovery_routes`,
    `test_restore_permissions`, `public_qualification/test_finish`,
    `test_launch_manifest` (no Docker).
- **Hand back:** the branch head, the design note, the suite summary, and anything
  in the contract you found wrong. The elephant runs the diff goldfish and merges.

## WP1: engine core, executor and policy

- **Owns:** `factory/durable/engine.py`, `executor.py`, `policy.py`, `report.py`,
  and tests `tests/factory/test_durable_engine*.py`.
- **Build:**
  - the batch workflow and case workflow on DBOS 3.4.0, following the design's
    "The case, step by step" and "What happens after each outcome";
  - the executor that composes `WorkerPool`, `WorkerChannel`, `Ledger`,
    `ArtifactStore`, `Sealer` and `KeyService`, always inside `guarded_run`;
  - `report.py`, the public scorecard from the engine tables.
- **Test against fakes of every other seam.** Write the fakes in your own test
  files, from the contract protocols.
- **Settle in your note** (from reviews 3 and 4):
  - the GATES deadline, from evidence;
  - ADMIT giving up its queue slot while it sleeps, and reading the registry when
    dequeued;
  - the engine's own stop history as a DIAGNOSTIC;
  - retrying a cancel after a transport failure before attempt n+1;
  - the minimum grant;
  - SEAL running only under the GATES versions;
  - waking waiting cases on settle;
  - registering queues before recovery enqueues;
  - checking the constructed instance for Conductor;
  - a finite request figure for batch-only steps;
  - a sub-minimum CASE grant diagnoses without starting, while a sub-minimum BATCH
    grant waits;
  - settling every `infra:cancelled` result with `settle_lost`.
- **Done when:** the mid-term exam passes. A batch of three cases on fakes survives
  `kill -9` of the engine at 20 random points, and no finished step runs twice.

## WP2: worker pool, provisioning and channel

- **Owns:** `factory/durable/workers.py`, `factory/durable/channel.py`, and tests
  `tests/factory/test_durable_workers*.py` and `test_durable_channel*.py`.
- **Build:**
  - `WorkerPool`: Boat creation and deletion under idempotency labels; adopting or
    deleting orphans on restart; release install and verification taking over
    `launch.sh:685-707`; writing `RELEASE.json`;
  - the release store keyed by bundle sha256;
  - the control side of `WorkerChannel`, per the contract's wire-protocol docstring.
    A transport failure is RUNNING.
- **Test against:**
  - real saved Boat CLI outputs (see `factory/boat_lifecycle.py` and its tests for
    existing captures);
  - a local fake of the worker command that obeys the docstring.

## WP3: sealer and artifact store

- **Owns:** `factory/durable/artifacts.py`, and tests `tests/factory/test_durable_artifacts*.py`.
- **Build:**
  - a `Sealer` using the `age` CLI, with the identity from `derive_keys` encoded as
    `AGE-SECRET-KEY-1...` (Bech32) and digests from `artifact_digest`;
  - an `ArtifactStore` with an R2 backend (reuse `factory/r2_upload.py` where it
    fits) and a local one.
- **Done when:**
  - a truncated upload is never visible;
  - ciphertext opens only with its scope key;
  - the same plaintext gives the same Ref within a scope and different Refs across
    scopes.

## WP4: failure classification

- **Owns:** `factory/durable/classify.py`, and tests `tests/factory/test_durable_classify*.py`.
- **Build:** an implementation of the `Classifier` protocol.
- **Done when:**
  - every stop kind in the 50 real non-dry-run scorecards in `sealed/` maps to an
    outcome;
  - a limit with no reset time gets a defined backoff computed from `now`.
- **Ship:**
  - the published-reason allowlist;
  - the top `opencode_error` causes from the real logs, with counts.

## WP5a: worker-side step runner

- **Owns:** `factory/durable/worker_step.py`; it is the only writer of
  `factory/run.py` in waves 1–2. Tests: `tests/factory/test_durable_worker_step*.py`.
- **Build:**
  - the worker side of the wire protocol: per-case lock, `attempt_busy`, tombstones,
    first-wins results, detach, the `RELEASE.json` version check, restore, run,
    snapshot;
  - the `run.py` hooks `context_for_step`, `run_step` and `retained_paths`;
  - turning off the in-process lifecycle branches listed in the design, including the
    in-process case budget. Under the engine, `money_ceiling_usd_micros` is the only
    money stop. Test: a snapshot with spent ≥ $50 and a $20 ceiling still runs a
    writer round.
- **Test on the public practice case.**
- **Done when:** the GATES snapshot-reuse test passes. A fresh worker restoring a
  GATES snapshot reuses that snapshot's passed gates.
- **Resolve** any `run.py` conflicts from the daily `factory-simplify` merges.

## WP6: ledger

- **Owns:** `factory/durable/ledger.py`, and tests `tests/factory/test_durable_ledger*.py`.
- **Build:** the `Ledger` protocol in the engine database, exactly per its
  docstring: draws, grants, labels, waste, `settle_lost`, idempotent replay.
- **Done when:**
  - concurrent reservations never exceed either limit;
  - five INFRA_ERROR attempts that spend money do not reduce the case's money;
  - replay gives an identical ledger;
  - `settle_lost` is also waste;
  - the three tie cases of the label rule hold;
  - a re-reserve after `raise_bound` returns the original Grant.

## WP7: key service

- **Owns:** `factory/durable/keys.py`, and tests `tests/factory/test_durable_keys*.py`.
- **Build:** the `KeyService` protocol, where the scoped VM key (founder-approved
  2026-10-29) wraps 32-byte scope keys.
- **Done when:**
  - a key leaves control-VM memory only inside `start_frame`;
  - no key appears in any engine record or log.
